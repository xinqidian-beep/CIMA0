4. “规则 vs 指定动作”审计
规则部分：k_demand 截断；按响应占比罚；两层 base 来自真实字段（cloud/collision）。

曾是指定动作（已识别/已改）：只罚当前层（逼翻）、local_response 占位（喂答案）、prev_winner 用 records 初值。

结论：winner 选择目前是规则驱动，非指定动作；但宏观切换由 base 决定，penalty 只调边际。

5. “涌现要素是否引入”审计（核心）
planet_activity：段内常数、段间指数衰减（比值 0.93~0.95），与 collision 变化点 95% 重合；只被记录，未进回路。

collision_count：层相关（层10均值84 vs 层11均值48），驱动 winner；来自 records 静态值。

_classify：连续 value → 三态标签（empty/zero/nonzero），唯一一次读数值。

_collision_type：纯离散标签 2×2 分类，value 参数传入但未使用。

cloud_state.receive：append value 到 cells，不读内容。

cloud_state.step：只 age+1、80 步删除，不读 value（已加 .get("clip") 门控，恒真、不触发）。

结论：离散标签驱动一切决策，连续数值降维后全程不被消费；系统开环、可预测。

6. 降维原则问题（待正式回答）
“value 在 _classify 里降维成三态标签，是否违反同构传递、自取所需？”

降维不违反同构传递：保留空/零/非零的定性结构，映射对得上。

违反“自取所需”的不是降维动作，而是“降维后无下游按需消费连续量”——所需方缺席。

结论：降维合法，消费端缺失。补的不是“取消降维”，而是“给一个下游按需消费”，且要符合极简（不引入新阈值/状态）。
