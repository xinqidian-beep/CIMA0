CIMA0_Core 命名规范检查清单 v1.0
总原则
目标：

通过命名强制保持模块自治，避免代码层面偷偷形成中心控制、全局理解、历史累积。

检查方式：

看到名字即可判断归属。

如果一个变量无法判断属于哪个域，默认不合格。

1. 域前缀隔离
IO 模块
允许：

io_
gate_
用于：

字节流

输入输出边界

外部接口

例如：

io_byte_stream
gate_input_sink
禁止：

memory_xxx
feature_xxx
semantic_xxx
因为 IO 不理解内容。

Cloud 模块
允许：

cloud_
sieve_
用于：

三值结构

空位

零负位

有效值

云内部演化

例如：

cloud_void_mask
cloud_neg_barrier
cloud_act_value
禁止：

world_model
global_state
knowledge_map
因为 Cloud 不是世界模型。

动力模块
允许：

kin_
field_
用于：

动力状态

局部演化

相位

振荡

漂移

例如：

kin_state
field_phase
field_drift
禁止：

controller
manager
optimizer
planner
因为动力系统不控制。

举手采样模块
允许：

proj_
sample_
用于：

局部采样

投影

黑盒观察

举手信号

例如：

proj_ephemeral_signal
sample_local_window
禁止：

judge
decision
supervisor
因为 Observer 不判断价值。

2. Cloud 三值拓扑命名
Cloud 内部必须明确：

空值 / 空位
后缀：

_void
_null
例如：

cloud_slot_void
含义：

不存在有效内容。

零值 / 负势位
后缀：

_neg
_barrier
例如：

cloud_field_neg
含义：

排斥、阻隔、负势。

有效值
后缀：

_act
_val
例如：

cloud_value_act
含义：

参与当前演化。

禁止：

cloud_data
cloud_feature
cloud_info
这种无法表达三值拓扑的名字。

3. 瞬时状态规则
所有临时观察：

必须明确生命周期。

允许：

_ephemeral_
_temp
例如：

omega_ephemeral_delta
sample_temp_value
禁止：

history
memory
archive
accumulated
除非未来明确设计长期记忆模块。

原因：

防止：

瞬时变化

↓

偷偷变成长期状态

↓

系统污染
4. 动作函数命名
演化
允许：

step_
drift_
例如：

step_state()
drift_phase()
表示：

时间推进。

观察
允许：

evaluate_
project_
例如：

evaluate_activity()
project_raised()
表示：

投影。

禁止：

control_
manage_
override_
因为这些词隐含：

中心控制。

kin/
 |

proj/

 | sample_local
6. 对当前代码影响
需要后续逐步调整：

planet.py
当前：

x
v
omega
作为最简数学变量可以保留。

但是如果进入大型结构：

建议：

kin_x
kin_v
kin_omega
或者：

类内部保持简洁，模块隔离依靠文件边界。

observer.py
当前：

baseline
activity
raised
以后建议：

proj_ephemeral_activity
proj_ephemeral_raised
sample_temp_baseline
避免 Observer 产生长期状态概念。

compute.py
需要重新检查。

因为：

allocate()
这个词偏管理。

应该考虑：

evaluate_compute_request()
或者：

step_compute()
避免“计算系统控制资源”的误解。

main.py
尤其注意。

禁止出现：

control_
manage_
global_
main 只能：

step_
或者：

run_
7. 后续开发顺序更新
下一阶段不增加功能。

顺序：

命名清洗

防止隐含中心化。

main 去中心化

main 只提供时间推进。

四模块边界确认

io / cloud / kin / proj。

最小长跑测试

不崩

不死

不重复控制。

再考虑外部字节扰动。

这个规范和之前“不死、不崩、不重复”的目标是一致的：

不是让系统更聪明，而是防止人为代码结构破坏局部自治。后续每次交付代码，可以先做一次“命名机械扫描”。
