这一次重新梳理后，项目路线其实清晰了很多。核心变化不是增加模块，而是**不断删除越权和重复结构**。

下面总结当前共识和后续计划。

---

# 一、当前最终设计原则（冻结版）

## 1. 局部存在原则

不存在全局观察者。

任何系统：

* 只能访问自己的局部；
* 只能根据自己的规则演化；
* 不知道整体。

包括：

* 人类；
* AI；
* 摄像头；
* CIMA实例。

---

## 2. 套娃同构原则

世界不是传统俄罗斯套娃：

不是：

```
大世界
 └── 小世界
     └── 更小世界
```

而是：

```
局部系统
   |
   +-- 自身状态
   +-- 自身规则
   +-- 局部输入输出
```

每一层结构类似，但不共享全局。

---

## 3. 模块职责原则

发现问题：

```
现象
 ↓
判断属于哪个能力
 ↓
定位模块
 ↓
修改该模块内部表达结构
 ↓
原则审计
```

禁止：

一个模块为了方便，替另一个模块承担职责。

---

# 二、CIMA0_Core 冻结结构

冻结，不继续加入硬件逻辑。

```
CIMA0_Core/

    core/

        planet.py
        observer.py
        compute.py
        io.py
```

---

## planet.py

职责：

内部最简动力系统。

负责：

* 状态；
* 局部动力规则；
* 时间演化。

不知道：

* observer；
* compute；
* io；
* 摄像头。

---

## observer.py

职责：

局部采样。

负责：

* 看哪里；
* 看多少；
* 形成局部描述。

不负责：

* 控制；
* 写回；
* 修改动力。

---

## compute.py

职责：

计算资源自洽。

负责：

* 预算；
* 稀疏采样；
* 举手机制；
* 局部补算；
* 时间尺度调整。

不负责：

* 判断世界意义；
* 控制目标。

---

## io.py

职责：

边界。

负责：

* 输入；
* 输出；
* 硬件接口。

不负责：

* 解释；
* 生成意义；
* 模拟世界。

---

```
CIMA0_Camera_Loop/
```

```
    io/

        output.py


    main.py
```

---

这里研究：

## 外部局部系统闭环

```
USB Camera Planet

        ↓

Input IO

        ↓

局部处理

        ↓

Output IO

        ↓

Display
```

---

这里的摄像头属于：

```
external/
```

不是：

```
core/
```

因为：

它代表外部物理系统。

# 六、目前最重要的设计纪律

以后每增加代码，先问：

### 这个东西属于谁？

例如：

| 问题       | 负责        |
| -------- | --------- |
| 摄像头怎么产生帧 | 外部硬件      |
| 怎么传输     | IO        |
| 怎么看      | Observer  |
| 算多少      | Compute   |
| 怎么演化     | Planet    |
| 怎么显示     | Output IO |

如果找不到负责人：

说明可能是多余模块。

---

目前方向已经从：

“堆一个人工智能系统”

转变为：

“建立多个局部自洽系统之间的边界耦合”。

下一步最合理的是：

**冻结 CIMA0_Core，创建 CIMA0_Camera_Loop，把真实摄像头输入和显示输出先跑成一个最小外部闭环。**

这样后续所有智能结构都建立在真实边界之上，而不是模拟世界之上。
