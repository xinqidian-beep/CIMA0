CIMA0_Core 架构原则清单（当前版）

用途：后续每次写代码前机械检查。
规则：找不到对应代码位置 = 不存在。
不进行“看起来合理”的解释。

一、最底层动力系统原则（PlanetEngine）
原则 1：最简引擎只有三个状态量

要求：

最底层动力单元只拥有：

x
v
omega

含义：

x：局部状态
v：状态变化
omega：内部时间尺度

禁止增加：

memory
reward
target
energy controller
global state

检查：

 PlanetEngine 是否只有 x/v/omega
 是否存在额外隐藏状态变量
 是否存在外部控制变量直接决定状态

不合格：

self.energy
self.memory
self.goal
原则 2：动力系统内部闭合演化

要求：

动力系统只根据：

自身状态
+
自身规则
+
外部扰动

产生下一状态。

形式：

(x,v,omega)

↓

local rule

↓

(x',v',omega)

禁止：

外部观察
        ↓
修改动力状态
原则 3：外部输入只能扰动，不能控制

允许：

step(external_force)

含义：

改变当前轨道。

禁止：

x=input

或者：

state = external_command

输入不能覆盖内部存在。

二、Cell 原则（动力组织层）
原则 4：Cell 不是最小单元

层级：

PlanetEngine
        |
        v
多个 PlanetEngine 集合
        |
        v
Cell

Cell 不拥有：

x
v
omega

这些属于 PlanetEngine。

原则 5：Cell 是局部动力集合，不是工程模块

Cell 内部：

可以存在：

多个 PlanetEngine

但是：

数量没有外部工程意义。

禁止：

Cell(size=128)

作为固定结构设计。

数量只能是：

内部形成
内部变化
初始临时状态

外部不能依赖。

原则 6：外部不能读取 Cell 全部内部结构

禁止：

cell.export_all_planets()

允许：

cell.sample_signal()

只提供压缩后的局部信号。

三、云系统原则（Cloud）
原则 7：云不是动力单元集合

Cloud 不是：

Planet列表

Cloud 是：

云矩阵状态空间

基础状态：

空值
空位
零值
负值

通过局部规则演化。

原则 8：云最终表达为三项状态

云内部：

矩阵演化

↓

统计压缩

↓

三项表达

三项表达不是：

人为指定语义。

不是：

第一个=能量
第二个=速度
第三个=意识

而是：

由云状态自然统计产生。

原则 9：云碰撞发生在公共媒介

禁止：

A云
 |
专用通道
 |
B云

允许：

云状态

↓

公共云场

↓

局部碰撞

↓

新状态
四、观察系统原则（Observer）
原则 10：观察系统独立

Observer：

只负责：

采样
压缩
判断局部偏离

不负责：

控制动力
修改计算
改变IO
原则 11：举手来自内部相对变化

举手：

不是：

固定条件触发

不是：

if x > threshold

而是：

当前活动

↓

自身历史基线

↓

相对偏离

↓

raised
原则 12：历史粗算，当前精算

历史：

低精度压缩：

baseline

当前：

高精度局部采样。

目的：

发现：

局部动态变化

不是：

保存完整历史。

原则 13：观察结果不是控制信号

禁止：

raised

↓

奖励

↓

增强动力

Observer 输出：

只是观察结果。

五、计算系统原则（Compute）
原则 14：计算系统独立

Compute 只负责：

计算资源
调度
时间片
精度

不知道：

动力意义
观察意义
全局结构
原则 15：计算不能改变动力规则

禁止：

计算系统

↓

修改 x/v/omega

计算系统只能决定：

什么时候算
怎么算
算多少
六、IO系统原则
原则 16：IO严格比特字节流

输入：

bytes

输出：

bytes

禁止：

IO层进行：

embedding
feature extraction
semantic understanding
原则 17：输入不降采样、不截断

禁止：

frame[:N]

禁止：

resize()

除非：

有明确来源
有记录
有确认
七、整体架构原则
原则 18：四个系统完全解耦

四个系统：

动力系统

计算系统

观察系统

IO系统

各自：

只负责自己的工作
不理解全局
不控制其他系统
原则 19：不存在中央理解者

禁止：

读取全部状态

↓

生成完整世界模型

↓

控制系统

外部永远只能：

局部采样
原则 20：复杂性来自长期运行，不来自预设结构

禁止：

提前加入：

智能模块
语义模块
中心管理器
特殊区域

允许：

最简规则

↓

大量局部交互

↓

长期运行

↓

复杂动态涌现
当前代码检查顺序

1. PlanetEngine
        ↓
2. Cell
        ↓
3. Cloud
        ↓
4. Observer
        ↓
5. Compute
        ↓
6. IO

每一步只增加对应层能力。

不允许跨层提前实现。
