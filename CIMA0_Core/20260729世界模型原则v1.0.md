核心世界模型原则 v1.0
1. 底层只有一个动力核心
不存在：

Planet系统
Cloud系统
Cell系统
这些是观察尺度。

底层：

FieldDynamics

状态
+
局部规则
+
时间演化
2. 结构不是被创建，而是被观察出来
不是：

创建Cloud
↓
Cloud运行
而是：

复杂动力场

↓

Observer采样

↓

发现局部高活跃区域

↓

命名为Cloud
Cloud是投影结果，不是底层实体。

3. 四模块重新理解
不是四个机器。

而是四种必要行为：

             最简动力核心

                  |
   --------------------------------
   |              |              |
  IO          Dynamics       Observer
                                  |
                              Compute
其中：

IO
边界交换。

只负责：

外部扰动
进入/离开
不理解。

Dynamics
唯一真实演化。

负责：

局部状态
局部规则
时间推进
不知道：

自己是什么

外面有什么

谁在观察

Observer
负责：

发现特殊区域
提高观察精度
生成快照
不修改。

Compute
负责：

计算资源有限

↓

决定观察预算
不是控制器。

代码最高检查标准
以后任何新增代码，都检查三个问题：

第一问
这个东西是不是底层真实存在？

如果只是：

名字

分类

观察结果

不要进入动力核心。

第二问
有没有重复制造规则？

例如：

错误：

CloudDynamics()
PlanetDynamics()
CellDynamics()
三个不同动力。

正确：

FieldDynamics()
同一规则。

第三问
有没有越权？

例如：

Observer：

错误：

cloud.modify()
Compute：

错误：

field.reset()
IO：

错误：

parse_meaning()
下一阶段代码应该进一步收敛：

目录：

CIMA0_Core/

core/

    field.py        # 唯一动力核心

    input_field.py  # IO边界

    observer.py     # 多尺度采样

    compute.py      # 算力预算


main.py             # 连接运行
其中：

cloud.py
planet.py

不再作为底层动力存在。

如果保留，只能作为：

View / Snapshot / Projection
而不是：

Engine
