核心命名规范总则
为确保四模块在“不死不崩不重复”的长跑运行中维持绝对的逻辑隔离与零污染，系统整体命名遵循域前缀隔离、拓扑后缀收敛、瞬时无状态的严苛约束。

1. 四大模块域前缀（Domain Prefixes）
所有内部类、函数及变量必须严格归属其特定模块，严禁跨模块交叉命名：

IO 边界流转模块： 统一使用 io_ 或 gate_ 前缀。

示例： io_byte_stream_adapter、gate_isomorphism_sink

三值云结构过滤模块： 统一使用 cloud_ 或 sieve_ 前缀。

示例： cloud_topology_reconstructor、sieve_potential_barrier

动力学与可塑性引擎模块： 统一使用 kin_ 或 field_ 前缀。

示例： kin_oscillator_matrix、field_plasticity_drift

举手采样投影模块： 统一使用 proj_ 或 sample_ 前缀。

示例： proj_ephemeral_raised、sample_blackbox_window

2. 三值云结构后缀（Cloud Topology Suffixes）
针对云矩阵内部重构的微观成分，变量命名必须明确映射其三值拓扑状态，严禁模糊定义：

空值空位（Null / Void）： 统一以 _void 或 _null 结尾。

示例： mask_bg_void

零值负位（Zero / Negative Potential）： 统一以 _neg 或 _barrier 结尾。

示例： tensor_repel_neg

有效数值（Active Value / Momentum）： 统一以 _act 或 _val 结尾。

示例： matrix_momentum_act

3. 瞬时快照与状态变量命名（Ephemeral Snapshot Rules）
为杜绝历史累积爆炸，所有关于瞬时快照的变量必须带有生命周期限定词：

瞬时对照变量： 必须带有 _ephemeral_ 或 _temp 标识，严禁使用 _history 或 _accumulated。

示例： omega_ephemeral_delta、gain_temp_snapshot

用后即弃状态： 统一采用单步覆盖式命名，禁止建立任何多维时间堆栈。

示例： state_current_step_only

4. 行为动词与函数命名（Behavioral Conventions）
反映系统在时间向量上的扰动与自反行为：

核心状态演化函数： 统一使用 step_ 或 drift_。

黑盒观测或举手判定函数： 统一使用 evaluate_ 或 project_。

严禁使用 control_、manage_ 或 override_ 等带有中心化强控制色彩的词汇，确保系统行为仅体现为“微弱的边界扰动与自然收敛”。
